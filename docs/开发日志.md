# 开发日志

> 这个文件**必须你自己写**，别人代写的日志一眼能看出来，而且它唯一的用处就是"证明你真的在场"。
>
> 规则很简单：
> - 每次坐下来干活，先写一行日期，再写"我本来想干什么"
> - 干完写"实际发生了什么"，卡住的地方写清楚报错原文或现象
> - 不用写得好看，写短、写具体、允许有情绪（"这里骂了一句"也行）
> - **不要回头美化前面的条目**。日志的价值就在于它是当时的，不是后来的
